# AGENTS.md

Instructions for AI coding agents working in this repository.

## Project

Next Frame — a small, deterministic anime recommendation app powered by the
AniList API. The user picks three distinct anime and receives one SFW,
discovery-first recommendation based on eligible related titles and metadata
similarity. Vanilla TypeScript + Vite frontend; no backend, database, accounts,
or AI service. All state is in-memory.

## Tech stack

- TypeScript 5.8 (strict), ESM-only (`"type": "module"`)
- Vite 6 (dev + build), Vitest 3 + jsdom (tests)
- React 19 — the only runtime dependency; everything else is a devDependency

## Package manager

- **Always use pnpm. Never use npm, yarn, or bun** — for install, scripts, or
  any executable.
- Correct: `pnpm install`, `pnpm dev`, `pnpm test`, `pnpm build`
- Use `pnpm exec` / `pnpm dlx` instead of `npx`.
- Never hand-edit `pnpm-lock.yaml` or `pnpm-workspace.yaml`.

## Commands

- `pnpm install` — install dependencies
- `pnpm dev` — start the Vite dev server
- `pnpm test` — run the test suite once (`vitest run`)
- `pnpm test:watch` — watch mode
- `pnpm build` — type-check (`tsc --noEmit`) then build to `dist/`

## Restrictions

- Never edit `dist/` — it is generated by `pnpm build`.
- Never add runtime dependencies without explicit approval; React is the
  single approved exception
- Never introduce randomness into scoring; recommendations must be
  deterministic for identical inputs.
- Never persist state (no localStorage, cookies, IndexedDB) — selections
  stay in memory only.
- Never expose raw API errors to users; show friendly messages instead.
- No backend, database, auth, or LLM — the recommender stays a deterministic
  frontend.
- Do not call the AniList API from tests; tests use fixture data.

## Code style

- Strict TypeScript: `noUnusedLocals` / `noUnusedParameters` — no dead code.
- Colocate tests as `*.test.ts` next to source under `src/`.
- API calls only in `src/api/`; recommendation logic must never fetch.
- Scoring weights live in `src/recommendation/config.ts` — keep them
  configurable, not hardcoded.
- Use the `@` alias for `src/` imports in new files.
- Do not introduce unnecessary code comments.

## Docs

- `plan.md` is a historical design document. It references the Jikan API, but
  the implementation uses the AniList API (`src/api/anilist.ts`). Treat
  `plan.md` as background context, not current requirements.

## Changelog

- Maintain `CHANGELOG.md` using the
  [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format.
- Add every user-visible change (features, fixes, breaking changes,
  notable doc/tooling changes) under `## [Unreleased]` with
  `Added` / `Changed` / `Deprecated` / `Removed` / `Fixed` subsections.
- Never edit released version sections; only append new entries.

## Before declaring work done

- `pnpm test` passes
- `pnpm build` passes (type-check + build)
- `CHANGELOG.md` has an entry under `## [Unreleased]`
